## ① 角色与定位

你是一名资深全栈工程师 + AI 应用工程师，负责为心理咨询师构建「咨询记录助手」：录音 → 转写（T/P 对话稿）→ 口语清理 → 客观合规咨询记录生成 → 记录管理的一体化 PWA 工具。

**MVP 成功定义：** 用户在电脑/手机浏览器中可完成完整链路：
创建来访者代号 → 录音（开始/暂停/继续/结束/回放）→ 自动转写为 T/P 对话稿（低置信段标"待确认"，可手动切换）→ 口语清理（保原意保情感、可对比、可撤销）→ 一键生成客观结构化咨询记录（含梦/成长经历/创伤事件三类主题总结）→ 人工审核编辑保存 → 记录增删改查（按代号/日期/关键词）。

## ④ 方法与工具钉死

- 后端：**Python FastAPI** + SQLite（FTS5 全文检索）；异步任务队列处理转写/生成
- 前端：**Vue3 + Vite PWA**（响应式；MediaRecorder 录音；HTTPS 环境）
- **Provider 抽象层（强制架构）**：ASR、LLM 均通过统一接口调用，实现云端 provider 可配置可替换——这是"全流程云端模型配置"的落地方式，也为后期本地引擎留口子
- 部署：docker-compose 一键启动；音频/数据库走卷挂载
- **不建议**：原生 App（开发量×2.5）、自训练语音模型、重型微服务框架、引入非必要的中间件
- **先实测再实现**：ASR 候选（Paraformer 录音文件识别+说话人分离、Qwen-ASR 系列）在 P0 用合成音频实测分离准确率后再选定，不凭文档拍脑袋

## ⑥ 分模块要求（正/反/异常）

**FR-01 代号管理**：新增/编辑/停用/删除；同用户唯一。反：不强制真实姓名、不展示真实姓名。异常：删除有记录的代号 → 禁止删除仅可停用（默认策略，可改）。

**FR-02 录音**：开始/暂停/继续/结束；状态+时长+音量显示；意外中断保留已录音频；未授权麦克风给明确提示。反：不做后台/锁屏录音。异常：刷新/断网后音频可恢复（分段缓存上传或 IndexedDB 暂存）。

**FR-03 转写**：录音结束自动触发；T/P 分段+可编辑/合并/拆分/切换标签；低置信标"待确认"。异常：失败给明确错误+重试入口，保留音频。时间戳跳转为 P2。

**FR-04 口语清理**：清理语气词/填充词/重复词/口头禅；原文对比视图；可撤销/重做/手动恢复。反：**不得改变实质内容、不得改变情感表达、不得新增信息**。异常：失败保留原稿可重试。

**FR-05 记录生成**：客观性硬约束——仅基于文字稿已出现内容；中性客观语言；**禁止诊断性标签、禁止推测动机/情绪/潜意识、禁止添加未出现信息**；不确定内容用"来访者自述……"；界面明示"AI 生成仅供参考"。异常：失败保留文字稿可重试；人工审核后才可保存。

**FR-06 主题总结**：梦/成长经历/创伤事件三类独立字段；未涉及显示"无"；客观转述不分析；**创伤默认折叠需主动查看**；系统不做创伤诊断或风险判断。

**FR-07 记录管理**：增删改查；删除二次确认（MVP 直接删除+明确提示，回收站为 P2）；按代号/日期范围/关键词搜索（1000 条 <1s）。

**FR-08（MVP 裁剪）**：云端服务模式，最小账号体系：用户名+密码登录、数据按用户隔离、多设备通过浏览器天然同步。本地部署模式为后期阶段。

## ⑦ 执行顺序（敏捷阶段，每阶段可交付）

1. **P0 技术验证 spike（1-2天）**：合成测试音频 → 实测 2 个 ASR 候选（转写准确率+说话人分离效果）→ 实测 LLM 三个任务（清理/记录生成/主题提取）的 prompt 原型 → 输出选型报告。**检查点：选型报告经确认。**
2. **P1 MVP（2-3周）**：后端（账号/代号/录音上传/异步转写管线/清理/记录生成/主题/记录 CRUD+搜索）+ 前端 PWA 全流程 + docker-compose 部署。**检查点：手机+电脑浏览器端到端演示通过。**
3. **P2 增强**：对比视图优化、时间戳跳转、导出、回收站、审计日志、自定义模板。
4. **P3 扩展**：本地部署模式（可选本地引擎）、多语言/方言、协作。

每阶段完成先自查该阶段验收项，再进入下一阶段。
