## 钉死的决策

### 1. clean v3 输出契约（语义重拼，段落不再 1:1）

```json
{
  "roles": {"A": {"role": "T", "label": "咨询师"}, "B": {"role": "P", "label": "来访者"}},
  "paragraphs": [
    {"speaker": "A", "source_seqs": [0, 1], "text": "合并清理后的完整语句"},
    {"speaker": "B", "source_seqs": [2, 3, 4], "text": "..."}
  ]
}
```

- `paragraphs` 是对原始段落的**语义重组**：同人碎片合并、断句重划；`source_seqs` 标注每段由哪些原始 seq 组成。
- **校验规则**（`_apply_clean_result` 重写）：
  - roles 覆盖全部代号（同 v2）；
  - 所有 `source_seqs` 拼接后必须恰好等于 `[0, 1, ..., n-1]`（每 seq 恰好出现一次、全局顺序不减）——缺段/重复/乱序都算失败；
  - 每个 paragraph 的 speaker 必须是已知代号，text 为非空字符串；
  - **跨说话人分派允许**（LLM 可纠正个别分错说话人的碎片），但不要求。
- 写回方式：**用重组后的 paragraphs 替换 segments**（清空旧段、按新段落重建：seq 重排、speaker/role/role_label/cleaned_content、start_ms/end_ms 取 source_seqs 首/末段的时间戳）。原始转写稿在落库前以 `代号: 文本` 逐行存进 `sessions.cleaned_text` 之前无持久化——**为保留审计底稿：把清理前的原始转写稿存入 `sessions` 表新增列 `raw_transcript`（Text, nullable，自愈机制自动补列）**。
- 坏 JSON/校验失败重试 1 次（同现状）。

### 2. clean/v3.md prompt（蒸馏 zxkane 方法论，中文，自含示例）

规则清单（按此写，勿发挥）：
1. 判定角色（同 v2：提问/引导/共情=咨询师；讲述自身经历/感受=来访者；同角色多人加序号）。
2. **碎片合并**：同一说话人被拆散的连续片段（一句话被拆成上下半句、口语碎片）合并为完整通顺的话语；一个 paragraph 可包含多个 source_seqs。
3. **上下文纠错**：修正明显的语音识别错误——同音字/别字；根据上下文纠正指代（例如全文语境是来访者谈妻子，后文的「他」应纠正为「她」）。
4. 删除填充词（嗯/啊/呃/就是说/那个 等），合并口吃与重复表达。
5. 修正语法使语句通顺，**但保留原意、情感强度与来访者用词风格；不新增内容、不总结、不诊断**。
6. 不合并不同说话人的话；不遗漏任何实质内容（每句原话的信息必须出现在输出中）。
7. source_seqs 必须覆盖全部输入段落，不重不漏。
8. 只输出 JSON。
示例区：给一个「拆句合并 + 他→她纠正」的完整示例（编一个贴近咨询场景的小样例）。

### 3. 分块调用（提速）

- **阈值**：segments ≤ 60 → 单次调用（现状路径）；> 60 → 分块。
- 分块规则：每块 ≤ 50 段，**在说话人轮换边界切块**（不拆同一人连续发言；若连续同人超 50 段则硬切）。
- 每块独立调用 clean v3（块内自含代号→角色判定）；后端合并：角色以**首次出现块的判定**为准（块间角色判定冲突时取先者），paragraphs 顺序拼接、seq 映射回全局。
- 任一块重试后仍失败 → 整个 clean 失败（同现状失败语义）。
- 测试用 fake LLM 断言调用次数与合并结果。

### 4. 前端进度条 + 转写简化显示

- **三阶段进度条**（上传卡片内、状态框上方）：① 转写 → ② 清理与角色判定 → ③ 生成记录。
- **阶段推导（纯前端，不加接口）**：`segments` 为空 → 阶段1；有 segments 无 record 且未 done → 阶段2；有 record → 阶段3；done → 全部点亮。失败时按同规则定位失败阶段并标红。
- **转写中间态简化**：阶段2期间（有 segments、无 role）气泡紧凑化——小内边距、无时间戳行、只显「说话人 A」+文本，对话稿标题旁标注「原始转写，正在按语义清理…」；清理完成后恢复正常气泡（每人一色、T 左 P 右、含时间戳）。
