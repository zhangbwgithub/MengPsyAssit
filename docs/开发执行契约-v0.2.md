## ① 角色与定位

你是一名资深全栈工程师 + AI 应用工程师，负责为心理咨询师构建「咨询记录助手」：录音 → 转写（T/P 对话稿）→ 口语清理 → 客观合规咨询记录生成 → 记录管理的一体化 PWA 工具。

## ② 目标与成功定义

**已钉死的方向性决策（用户拍板，不给二次选择）：**

| # | 决策 | 选择 | 理由 |
|---|------|------|------|
| D1 | MVP 形态 | **云端方案优先** | 目标设备以 Windows/mac 为主、不保证强显卡；云端方案不挑平台 |
| D2 | AI 能力路线 | **全流程云端模型**（转写/清理/记录生成/主题提取全部走云 API） | 最小系统必须包含云端模型配置；本地引擎为后期选项 |
| D3 | 转写引擎 | 云端 ASR API（DashScope Paraformer / Qwen-ASR，P0 实测后定） | 省事便宜、带说话人分离 |
| D4 | LLM | Qwen 为主，Deepseek 可切换（均为云 API，配置化） | 用户两者皆可 |
| D5 | 客户端 | PWA Web 应用（响应式覆盖电脑+手机浏览器） | 一套代码、满足浏览器麦克风+HTTPS 要求 |
| D6 | 知情同意功能 | 按 PRD 推迟（MVP 不做） | 用户决定；已记录此合规风险 |

**MVP 成功定义：** 用户在电脑/手机浏览器中可完成完整链路：
创建来访者代号 → 录音（开始/暂停/继续/结束/回放）→ 自动转写为 T/P 对话稿（低置信段标"待确认"，可手动切换）→ 口语清理（保原意保情感、可对比、可撤销）→ 一键生成客观结构化咨询记录（含梦/成长经历/创伤事件三类主题总结）→ 人工审核编辑保存 → 记录增删改查（按代号/日期/关键词）。

## ④ 方法与工具钉死

- 后端：**Python FastAPI** + SQLite（FTS5 全文检索）；异步任务队列处理转写/生成
- 前端：**Vue3 + Vite PWA**（响应式；MediaRecorder 录音；HTTPS 环境）
- **Provider 抽象层（强制架构）**：ASR、LLM 均通过统一接口调用，实现云端 provider 可配置可替换——这是"全流程云端模型配置"的落地方式，也为后期本地引擎留口子
- 部署：docker-compose 一键启动；音频/数据库走卷挂载
- **不建议**：原生 App（开发量×2.5）、自训练语音模型、重型微服务框架、引入非必要的中间件
- **先实测再实现**：ASR 候选（Paraformer 录音文件识别+说话人分离、Qwen-ASR 系列）在 P0 用合成音频实测分离准确率后再选定，不凭文档拍脑袋

- 界面语言：中文

## ⑥ 分模块要求（正/反/异常）

**FR-01 代号管理**：新增/编辑/停用/删除；同用户唯一。反：不强制真实姓名、不展示真实姓名。异常：删除有记录的代号 → 禁止删除仅可停用（默认策略，可改）。

**FR-02 录音**：开始/暂停/继续/结束；状态+时长+音量显示；意外中断保留已录音频；未授权麦克风给明确提示。反：不做后台/锁屏录音。异常：刷新/断网后音频可恢复（分段缓存上传或 IndexedDB 暂存）。

**FR-03 转写**：录音结束自动触发；T/P 分段+可编辑/合并/拆分/切换标签；低置信标"待确认"。异常：失败给明确错误+重试入口，保留音频。时间戳跳转为 P2。

**FR-04 口语清理**：清理语气词/填充词/重复词/口头禅；原文对比视图；可撤销/重做/手动恢复。反：**不得改变实质内容、不得改变情感表达、不得新增信息**。异常：失败保留原稿可重试。

**FR-05 记录生成**：客观性硬约束——仅基于文字稿已出现内容；中性客观语言；**禁止诊断性标签、禁止推测动机/情绪/潜意识、禁止添加未出现信息**；不确定内容用"来访者自述……"；界面明示"AI 生成仅供参考"。异常：失败保留文字稿可重试；人工审核后才可保存。

**FR-06 主题总结**：梦/成长经历/创伤事件三类独立字段；未涉及显示"无"；客观转述不分析；**创伤默认折叠需主动查看**；系统不做创伤诊断或风险判断。

**FR-07 记录管理**：增删改查；删除二次确认（MVP 直接删除+明确提示，回收站为 P2）；按代号/日期范围/关键词搜索（1000 条 <1s）。

**FR-08（MVP 裁剪）**：云端服务模式，最小账号体系：用户名+密码登录、数据按用户隔离、多设备通过浏览器天然同步。本地部署模式为后期阶段。

## ⑦ 执行顺序（走骨架 + 垂直增量，每增量可交付可演示）

> 原则：**最短路径先跑通最薄的端到端主链路（走骨架），再按垂直增量逐段加厚功能**。每个增量 2-3 天，以向陛下演示收尾；不为完整而推迟可演示。

1. **P0 技术验证（0.5-1 天）**：合成测试音频 → ASR 候选实测（准确率+说话人分离）→ 「清理/记录生成」两个 prompt 骨架验证 → 选型钉死。**检查点：选型报告经确认。**（环回采集 PoC 推迟至 P2，不阻塞最小系统；主题提取 prompt 随 S3 增量验证。）
2. **S0 走骨架（2 天，首个可演示版）**：上传音频文件 → 转写 T/P 对话稿 → 最简清理 → 最简记录生成 → 单页展示。故意不做：录音（文件上传代替）、分片续传、编辑、映射、登录、撤销、搜索。**检查点：合成音频端到端演示通过，tag `v0.1-skeleton`。**
3. **S1 录音+上传加固（FR-02）**：MediaRecorder 录音、分片上传断点续传、IndexedDB 暂存。→ tag `v0.2-recording`
4. **S2 文字稿编辑+说话人映射（FR-03）**：段落编辑/合并/拆分/切换、点选映射、待确认高亮。可与 S1 并行。→ tag `v0.3-editing`
5. **S3 清理加固+记录+主题（FR-04/05/06）**：对比视图+撤销、记录生成加固（接第二个 LLM 验证抽象）、主题三字段。→ tag `v0.4-clean-record`
6. **S4 账号+代号+记录管理（FR-08/01/07）**：真实认证、代号管理、记录 CRUD、FTS5 搜索、管理界面。→ tag `v0.5-full-app`
7. **S5 部署+端到端验收**：docker-compose、HTTPS、性能验收、双端全流程演示。→ tag `v1.0-mvp`
8. **P2 会议模式**：环回采集 PoC（补做）→ Tauri 桌面端 → 实时字幕。**P3 增强 / P4 扩展** 滚动细化。

每增量完成先自查验收项（逐条报 PASS/FAIL/NOT RUN），演示通过才进入下一增量。任务级分解与模型指派见 `01-任务书.md`。

## ⑧ 范围收缩（本次不做清单）

原生 App、多人协作/机构管理、PDF/Word 导出、回收站、审计日志、知情同意流程、自定义记录模板、微信/手机号登录、第三方系统对接、方言支持、本地离线转写引擎、云端自动升级。——以上严格按 PRD 第 10 节归入后续阶段，**禁止镀金提前做**。增量内同样适用：S0 不做的项（录音/编辑/登录等）禁止在 S0 内顺手实现。

## ⑨ 完成条件与诚实条款

**验收（P1 出口 = S5）**：FR-01~07 验收标准逐条通过；性能达标（1万字清理<60s、记录生成<120s、1000条搜索<1s、支持180分钟录音）；手机/电脑双端演示通过。**每条验收项必须给出 PASS/FAIL/NOT RUN + 证据**（证据制，遵循 governance 技能）。

**防御条款**：
1. 防伪造：未知信息标"未知/待确认"，不编造测试结果与数据
2. 防幻觉汇报：API 调用、转写效果、性能数字必须有真实输出证据；Reasonix 自称"已完成"不作数，以大统领实测为准；未验证项报 NOT RUN 并列验证步骤
3. 防占位交付：不留 TODO/占位内容作为阶段交付
4. 防跳步：每增量先自查验收项再继续；编译通过≠功能验收，单测过≠端到端通过，分层陈述不混淆
5. 防镀金：严格遵守第 ⑧ 节清单与增量边界
6. **敏感数据边界**：测试只用合成音频，不接触/不落盘真实咨询数据；API Key 仅存 .env，不进 git、不进日志
7. 防基线破坏：迭代基于现有基线增量修改，不推倒重写
8. **交接义务**：增量收尾与上下文压缩前更新 `docs/handoffs/CURRENT.md`，必答四问——边界变了什么/证据是什么/什么没验证/如何回滚
